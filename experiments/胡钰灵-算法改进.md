# 算法研究与改进实验 



一、我在团队里的角色（成员）

- 负责什么：理解基线之后，探索一项有明确目的的改进方案。先从简单、可解释的改进开始，不直接上深度学习。
- 允许选的改进方向（文档给的菜单）：
  1. 比较不同 CSP 组件数量（`n_components`）
  2. 比较不同的 LDA 正则化设置（`reg`）
  3. 在合理实验设计下比较不同滤波频带（如 8–30 之外试别的）
  4. 调研其他适合运动想象 EEG 的分类方法

二、我的交付物

| # | 交付物 | 大白话 | 我们手头的素材 |
|---|--------|--------|----------------|
| 1 | 一项明确的改进假设 | "我认为改 X 能让结果变好" | 调参扫描的试错经验 |
| 2 | 对应的实验设计 | 怎么改、其他全不动，只动一个旋钮 | 单因素变量法 |
| 3 | 可以运行的代码/脚本 | 组长能一键跑起来的 .py | `tuning_A01.py` 升级版 |
| 4 | 与基线相同指标下的结果 | 同样用交叉验证，才能公平比 | tuning_summary.csv |
| 5 | 对实验结果的解释 | 为啥这个设置好/不好 | "一次只转一个旋钮"的结论 |

关键纪律（文档"重要"提示）：如果拿同一套交叉验证反复挑最优参数，最终分数会偏乐观。
→ 严格评估要用嵌套交叉验证或独立测试集。这正是我们一直守的"数据泄漏红线"。

三、学习地图（从零基础到交付）

# 阶段 0：看懂地基（已完成 ✅）
- 数据形状 (288, 25, 751) 是啥 → 已学
- mne 读 GDF / 事件标签 / 重新编号陷阱 → 已学
- 滤波 8~30 Hz 为什么 → 已学（`filter_demo.py`）

# 阶段 1：必懂的两个旋钮（要学的概念课）
- CSP（空间特征提取）：把 25 路脑电"拧成几条主线"
  → 因为改进项 1 就是"拧多少条（n_components）"
- LDA（分类器）：在拧好的线上画分界线
  → 因为改进项 2 就是"分界线糊多严（正则化）"

# 阶段 2：会提问（交付物 1）
- 怎么把"我觉得 CSP 组件数有用"变成可验证的假设
- 判断一个假设"能不能被实验证明或推翻"

# 阶段 3：会设计实验（交付物 2）
- 单因素变量法：只动一个旋钮，其他全锁死（数据、滤波、分段、交叉验证划分）
- 为什么同时改两个东西就"说不清是谁起的作用"
- 嵌套交叉验证 / 独立测试集：防"调参自欺"

# 阶段 4：会跑对比实验（交付物 3+4）
- 把 `tuning_A01.py` 升级成规范的对比脚本（一次只转一个旋钮）
- 每组设置都输出：交叉验证、分类报告、混淆矩阵（跟基线同一套指标）
- 会读 tuning_summary.csv / 图

# 阶段 5：会解释结果 + 写交付（交付物 5）
- 用"这是啥/为啥/咋做的/结果说明啥"四阶梯解释每个结论
- 产出一份成员4报告：假设 → 设计 → 代码 → 结果表 → 解释
- 通过组长视角自查：评估规范是否统一、是否可复现、是否防泄漏
